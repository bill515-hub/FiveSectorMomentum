## T1（=H2）`trading_fee_rate` 单位全品种审计 + 独立影响重算

**要回答**：费率字段是"千分数(÷1000)"还是"万分数(÷10000)"？哪些是费率型？T 的特例是否正确？修正后 v3 / S1 少计多少手续费？

**输入（只读）**
- `data/v3/fees/tushare_fut_settle_daily_raw.pkl`
- `outputs/v3_20260902_001129/00_formal__formal_baseline/fills.pkl`
- `outputs/v4_2_20260903_091241/S1__strategy_sleeve_20skip5_250_equal_risk/fills.pkl`
- `data/v3/fees/historical_fee_rules.pkl`（仅对照，不用于独立复算）

**独立实现算法**
1. 直接用 `instrument` 列（无需从合约前缀提取）。先做**特例识别**：找出 `trading_fee` 缺失/为 0 但 `trading_fee_rate>0` 且 `exchange=='CFFEX'` 的品种（预期=T），标记为"固定费误存于 rate 字段"，其 `trading_fee_rate` 的数值就是**元/手**，不参与 ÷1000/÷10000。
2. 真费率型 = `trading_fee_rate>0` 且 `trading_fee` 缺失/为 0 的非 CFFEX 品种（预期=RB、SP；RU 为固定 3 元，`rate=0` 应排除）。
3. 对每个真费率型品种，输出全历史 distinct `trading_fee_rate` 值 + 生效日期区间（预期 RB=[0.1,0.3]、SP=[0.02,0.05]）。
4. 对每个值同时按 `÷1000` 与 `÷10000` 换算，对照官方公告（RB 基准月万1、2023 一段万3；SP 万0.5→2026-07 万0.2），并可用 `ak.futures_comm_info()` 当前值辅助；输出"÷1000 对齐官方 / ÷10000 差 10 倍"的结论表。
5. **独立影响重算**（不读框架规则表，直接读原始费用 pkl）：
   - 建映射：`(instrument, trade_date)` → `{trading_fee_rate, trading_fee, 是否CFFEX特例}`。
   - 对每笔 fill：`date` 对齐 `trade_date`；费率型用 `fee_rate=trading_fee_rate/1000`、`fee_per_lot=0`；固定型用 `fee_per_lot=trading_fee`、`fee_rate=0`；T 特例用 `fee_per_lot=trading_fee_rate`（元/手）、`fee_rate=0`。
   - `exchange_fee = |quantity| × (fee_per_lot + price × point_value × fee_rate)`；`client_fee = exchange_fee × 1.5`。
   - 逐笔 diff `client_fee` vs `fills.commission`，分别汇总 v3 基准与 S1 的总差额；同时输出框架当前（÷10000）口径下的对照值（用 `fills.fee_rate` 反推即可，但以重算为准）。

**判定标准**：若 RB/SP 的 `÷1000` 与官方一致、`÷10000` 差 10 倍，且 T 特例按元/手处理正确 → H2 成立。独立重算差额与（v3≈48.7 万、S1≈150.6 万）同量级（±20%）即复现；否则说明影响计算有误。

**产出**：`reports/T1_fee_unit_audit.md`、`fee_rate_distinct_by_instrument.csv`、`fee_impact_recompute.csv`。

## T2（=H1）端点行为诊断 + 锁板方向重建与成交重放

### 重要前置事实
- `data/raw/tushare/fut_settle.pkl` 与 `ft_limit.pkl` 均为 **0 行 0 列**（空 DataFrame）。
- 但 `data/v3/fees/tushare_fut_settle_daily_raw.pkl` 有 36040 行且含 settle+保证金+手续费——**说明 `fut_settle` 端点能返回数据**。所以 H1 的"fut_settle=0"不是数据源缺失，而是 `data_source.py` 的 `_download_contract_endpoint("fut_settle", optional=True)` 管线 bug（或字段/批量参数/optional-disable 逻辑问题）。

### T2a 端点行为诊断（联网 + token）
1. 用 `tushare.pro_api` 最小化单合约调用，分别记录"有数据/空/报错"三种结果：
   - `fut_settle(ts_code='RB2410.SHF', start_date='20240102', end_date='20240131', fields='ts_code,trade_date,settle,trading_fee,trading_fee_rate,long_margin_rate,short_margin_rate')`
   - `ft_limit(ts_code='RB2410.SHF', start_date='20240102', end_date='20240131', fields='ts_code,trade_date,up_limit,down_limit')`
   - 再用 1 个 CZCE 合约（如 `MA401.ZCE`）与 1 个 CFFEX 合约（如 `T2403.CFX`）各试一次。
2. 重点诊断：对比"单合约逐个调用"与"`ts_code=[6个合约列表]` 批量调用"的返回差异，定位 `data_source.py` 为何拿到 0 行；`ft_limit` 是否真的不可用。

### T2b 锁板方向重建与成交重放（离线，不依赖 ft_limit）
1. 读 `data/raw/tushare/fut_daily.pkl`（有 `pre_settle, settle, vol, oi`）。
2. 锁板日判定：`high==low` 且 `vol>0`；锁板方向：`sign(settle - pre_settle)`（>0 涨停锁、<0 跌停锁、==0 记异常）。
3. 读 v3 基准与 v4_2 S1 的 `fills.pkl`，对落在锁板日的成交按 `sign(quantity)` 判多空，标记顺/逆锁板方向。
4. 复现"锁板 12 天 / 成交 7 笔 / 4 笔逆方向"，逐笔列（日期、合约、方向、量、价格、run）；与 `audit_20260903_v2` 声称值比对。
5. 定性补充：同方向成交在锁板日也隐含"全额成交"的乐观假设，记录之。

**判定标准**：复现 12/7/4 且逆方向清单一致 → H1 后果链坐实；不一致 → 定位分歧。

**产出**：`reports/T2_endpoint_and_locked_board.md`、`locked_board_days.csv`、`locked_fill_replay.csv`。

## T3（=#8）保证金约束敏感性（离线；真实逐日保证金率已可得）

**要回答**：静态兜底保证金率（×1.25）相对**真实逐日保证金率**，会多大程度改变 65%/78% 保证金约束触发结论？

**关键修正**：真实逐日 `long/short_margin_rate` 已在 `data/v3/fees/tushare_fut_settle_daily_raw.pkl`（35742/36040 非空），**无需等 T2a 重拉**。

**输入（只读）**
- `data/raw/tushare/fut_daily.pkl`（settle）
- `data/normalized_v2/contract_meta.pkl`（point_value, fallback_margin_rate）
- `outputs/v3_20260902_001129/00_formal__formal_baseline/positions.pkl`（列 `date, contract, instrument, position`）与 `daily_equity.pkl`（已含 `margin, commodity_margin, margin_utilization, commodity_margin_utilization`）

**独立实现算法**
1. 逐日逐合约算 `margin = |position| × settle × point_value × margin_rate × 1.25`，margin_rate 用四种场景：
   - S0 = `contract_meta.fallback_margin_rate`（现状静态兜底）
   - S1 = 静态 × 1.5；S2 = 静态 × 2.0
   - S3 = 真实逐日率：按 `(contract=ts_code, date=trade_date)` 从费用原始 pkl 取 `long_margin_rate`（多头）或 `short_margin_rate`（空头）
2. 先用 S0 复算并与 `daily_equity.margin / commodity_margin` 记录值比对（校验复算正确性，允许 tick/舍入级残差）。
3. 计算每日 `commodity_margin/equity` 与 `total_margin/equity`，对照 0.65/0.78，输出各场景触发日数、峰值占用、触发日期清单。
4. 对"触发日差异"，从 `targets.pkl`/`orders.pkl` 估算被约束多砍/少砍的手数（不重跑引擎，只做事后敏感性）。

**判定标准**：S0/S1/S2/S3 触发结论是否随场景翻转。翻转明显 → 静态率是承重假设，需在管线修复后重跑正式回测；一致 → 影响有限。

**产出**：`reports/T3_margin_sensitivity.md`、`margin_scenario_utilization.csv`。

## T4（=#11+#12）独立复现包（换实现重算关键数）

**要回答**：审计方的"会计残差 0、平今 0、覆盖 100%、退市在库、v1 拼接失败 104、锁板 12 天"是否可被另一套实现复现？

**独立实现算法（纯 Python/numpy，不复用框架与审计脚本）**
1. **会计恒等式**（v3 基准 + v4_2 S1）：读 `daily_equity.pkl`，验 `equity[t]-equity[t-1]==net_pnl[t]`、`net_pnl==gross_pnl-fees`、`Σnet_pnl==期末equity-初始`，输出最大残差。
2. **平今=0**：读 `fills.pkl`，统计 `transaction_type` 出现值（预期仅 `open, close_non_today`，`close_today` 计数=0）。
3. **主力序列覆盖=100%（内部一致性）**：读 `normalized_v2/mapping.pkl` 与 `fut_daily.pkl`，按 mapping 逐日核对主合约有 bar（`vol>0 且 close 非空`），输出缺日数。（日历外部正确性属 T6，此处只证"映射日都有 bar"。）
4. **退市在库**：读 `fut_basic.pkl` 与 `fut_daily.pkl` 各自 distinct ts_code per instrument，输出"上市合约数/实际装载数/已退市仍在库数"。
5. **v1 拼接失败=104**：读 `data/normalized/diagnostics.json` 的 `panama.stitch_failures`（列表），`len()==104`；再抽样 5 例用 `mapping + fut_daily` 重算"新旧合约 10 个交易日内有无重叠报价"验证确为失败。
6. **锁板 12/7/4**：另写一套代码（与 T2b 不同实现）交叉比对。

**判定标准**：所有数字与审计声称一致 → 复现通过；不一致 → 定位分歧并升级。

**产出**：`reports/T4_independent_recompute.md`、`recompute_accounting.csv`、`recompute_coverage.csv`、`recompute_survivorship.csv`。
