## 1. 变更原因与研究边界

v6.3 Phase 0 在冻结的 `data/normalized_v2/mapping` 中发现两次 SC 主力合约到期月份倒退。原规范同时要求“映射到期日单调不倒退”和“G01/G02 精确复现 v6.2 B03/B04”，两者不能同时成立，因此 v6.3 已按纪律在绩效前停止。

本轮经用户授权另起 v6.3a。只修复该类主力映射倒退，不修改任何 v2—v6.3 历史文件，不改变信号、风险、成本、成交、保证金、统计或推荐规则。v6.3 v1.1 的 17 场景和 19 次 attempt 上限全部保留。

## 2. 唯一允许的映射修复

对每个品种按交易日顺序处理供应商映射：

1. 首个可用合约成为已接受合约；
2. 若当日建议合约到期日不早于已接受合约，则接受建议；
3. 若建议合约到期日更早，则保持已接受合约，但仅当该合约当日有正成交量、有效收盘价，且距离到期不少于原配置的20个自然日；
4. 若上述保持条件不满足，立即停止并报告 blocker，不允许查看未来数据选择替代合约；
5. 保持持续到建议合约到期日重新达到或超过已接受合约；
6. 修复来源码固定为 `V6_3A_CAUSAL_HOLD_NO_BACKWARD_EXPIRY`。

判断仅使用当日收盘时已经可得的合约、到期日和当日行情。修复后的映射用于重新构造 Panama 加减价差序列。追加未来数据不得改变既有日期的修复映射或 Panama 点差。

## 4. 冻结场景、统计与停止条件

场景顺序保持：`G01/G02 → S01…S07 → D01/D02 → T01/T02/T03 → N01/N02/T04`。完整历史场景17个，attempt上限19。三周期、成本压力、next-close完整结算、Bootstrap成员、Westfall—Young、期限结构阈值、推荐否决项和计分项全部逐字继承 v6.3 v1.1。

以下任一情况立即停止：

- 修复后的任一品种映射仍出现到期日倒退；
- 保持的合约当日无有效行情、成交量不正或距到期不足20日；
- 追加未来数据改变历史映射或Panama点差；
- 冻结源码、输入、注册表或配置哈希变化；
- 账户、成本、next-close结算、因果字段或确定性闸门失败；
- attempt超过19或账户权益耗尽。

全部结果继续标记 `PROVISIONAL_DAILY_ONLY_CAUSAL_EXECUTION`。本轮不进入其他研究。
