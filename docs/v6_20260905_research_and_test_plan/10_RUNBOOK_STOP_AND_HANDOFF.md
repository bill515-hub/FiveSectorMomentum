# v6 执行手册、停止规则与交接标准

## 1. 执行前只读检查

1. 记录原仓 Git 状态和所有历史目录哈希；
2. 确认没有修改 v2—v4.2 源码、配置、缓存和输出；
3. 读取本目录所有文件并生成计划哈希；
4. 解析 `V6_MACHINE_REGISTRY.yaml`，核对 44 场、22 策略、阈值和人类注册表完全一致；
5. 创建 v6 新源码包、配置、数据快照和唯一输出目录；
6. 由机器注册源生成/校验 resolved config，并把机器注册源和 `06_EXPERIMENT_REGISTRY.md` 同时复制进输出锁定；
7. 生成项目级 `outputs/V6_GLOBAL_ATTEMPT_LEDGER.csv`；每次启动前追加并原子落盘，不能因新时间戳目录而重置；
8. 运行 secrets 扫描，确保 token 不进入日志和 manifest。

所有完整历史运行只能由单一 v6 launcher 启动。launcher 必须取得项目级 `outputs/.V6_ATTEMPT_LEDGER.lock` 的排他文件锁，在锁内检查上限、先预占唯一 `attempt_id` 并写 `STARTED`、fsync/原子替换账本后再释放锁和启动进程；结束后在同一锁内改为 `COMPLETED/FAILED/INTERRUPTED`。崩溃遗留的 `STARTED` 仍计一次。禁止两个进程先各自读计数再并发追加。

## 2. Phase 0：规范和迁移骨架

交付：

- v6 数据 schema；
- 独立日历和字段单位 registry；
- 旧 v3/v4.2 只读 adapters；
- resolved config；
- 事件类型和稳定原因码；
- 测试分类和依赖锁。

此阶段不看新的策略绩效。

Phase 0 只定义 schema 与构建器，不把尚未建成的规则误记为已冻结输入。进入 Phase 2 前必须由 Phase 1 实际生成并一次性冻结 `legacy_compat_snapshot` 与 `corrected_v6_snapshot`；两者冻结时间都必须早于 A01 启动时间。

## 3. Phase 1：规范数据、规则和可行性

1. 先运行五所 10 合约 `ft_limit` 权限探针，不先假定“批量问题已修好”；
2. 逐合约下载/核验 `fut_settle`，先生成 2015—2020、品种×年和 T/商品分组覆盖；
3. 对 RB/SC/M/TA/T 固定 75 个分钟样本核验 `next_open`；
4. 若 `ft_limit` 无权限则转官方规则推导，并用全历史 high/low 必要条件 oracle 与固定挑战集验证；
5. 建历史手续费规则和单位 registry；
6. 建逐日方向性保证金表；
7. 建上下限表并验证开盘前可知；
8. 构建并冻结两个输入：只读 `legacy_compat_snapshot` 和 `corrected_v6_snapshot`；后者的共享行情、元数据、映射和 Panama 字段必须逐键等于冻结旧快照，只新增修复日历、规则和来源字段；
9. 运行数据、日历、Panama、规范表哈希和前缀测试；
10. 人工核验 RB/SP/T/AL/SC 费率锚点、固定锁板挑战集和 RU2505 旧腿；
11. 在任何完整历史 attempt 前，把迷你市场中 B07/B08 涉及的手续费、限价、保证金目标缩量、日终超限诊断、`ACCOUNT_INSOLVENT` 停止、双 cap、袖套净额、跨零、换月、拒单和部分成交分支全部跑通；不得实现 65%/78% 经纪商强平订单。

随后在 A01/A04 已有冻结订单和持仓键上实际运行 G0-DATA-FEASIBILITY 与 G1 覆盖审计：限价必须 100%，保证金覆盖须满足总组合、商品和 T 各≥95%，关键临时提保暴露日 100%，费率单位锚点必须通过。冻结两个 snapshot 的哈希和差异白名单后才可启动 A01；若不达标，停止且不启动任何完整历史运行。

## 4. Phase 2：兼容复现与日历桥接

按 A01—A06 顺序运行。每次立即生成逐表 diff。任何差异先判断：

- 排序/类型展示差异；
- 环境浮点差异；
- v6 适配错误；
- 历史文件自身不完整。

只有有底层证据的解释才可接受。最终净值接近但订单不同不算通过。A06 是原 v3 的日历单因素桥接；B01 必须以 A06 而非 A01 为直接比较对象。

## 5. Phase 3：单因素纠错阶梯

按 B01—B08 顺序：

1. 引擎每个结算日和每个真实订单事件后立即检查手数/现金/费用核心恒等式，失败立即中止；场景结束后再做完整独立账户勾稽；
2. 生成与前一级冻结路径和动态路径的差分；
3. 检查不应改变的信号/目标是否保持；
4. 标记变化首次发生的日期、事件和原因；
5. 人工复核最大 20 个金额差和全部锁板差异；
6. B05/B06 完成逐日保证金单因素后，B07/B08 只新增“所有风险放大及正常 buffer 后的最终流动性/OI 硬检查”；
7. B07/B08 通过 G1—G7 后才继续。

不能从“手续费增加多少”直接推断最终净利润应减少同额。

## 6. Phase 4：固定研究复核

运行 C01—C03，然后：

- 更新 20skip5、250、50:50 袖套的独立收益；
- 重算成本节约、真实合约净额和 buffer；
- 重算回撤期相关性和板块来源；
- 比较固定 3 tick 压力；
- 不改变信号、权重或滑点点位。

## 7. Phase 5：锁板政策

运行 D01、D02。人工检查每一笔触发：

- runner-up 是否在 t 日预生成；
- 原订单与条件单是否重复成交；
- 顺延是否恰好一个交易日；
- roll 旧腿是否被错误替代；
- 部分成交和预算是否重复；
- 卖出侧两个场景是否只有预注册差异。

锁板事件过少时应报告统计功效不足，不能因某个政策收益高就推荐。

## 8. Phase 6：完整候选和方法学审计

只有 Phase 0—5 全部通过，才执行剩余 18 个候选。必须一次决定启动完整 E 组；不能边看结果边停在有利子集。每次启动前统一要求 `48-attempt_count >= 44-effective_count`，右侧包含从未启动和已失败但尚未有效完成的场景；仅当前 19 场全为 effective 时，E 组入口才可简写为至少剩余 25 次。否则在开始下一家族前停止，不能制造一个注定无法完成的候选集合。

若 E 组中途因技术失败停止，已完成场景目录全部保留，E 组汇总的 `family_status` 标 `INCOMPLETE_FAMILY`，顶层标 `FAILED_GATE`；不得用该子集做 22 策略排名、Bootstrap 或选择结论。修复后只能在剩余全局 attempt 储备内继续原注册场景。

完成后：

1. 构建 22 策略同日期日收益矩阵；
2. 执行联合移动分块 Bootstrap；
3. 执行多重比较调整；
4. 运行 F01 真实滚动选择；
5. 输出每窗训练分数、选择和过渡成本；
6. 明确这仍是受历史观察影响的伪样本外。

## 9. Phase 7：有限诊断

运行 G01/G02 协方差统一缩放消融和 H01/H02 代理费率压力。它们只解释模型，不参与 22 个基础策略排名。

## 10. Phase 8：发布

1. 单元/集成/事件重放测试跨进程重复；完整历史确定性仅用预注册 I01/I02；
2. CSV/pickle 一致性检查；
3. 独立会计复算；
4. 生成四份中文报告和交接文档；
5. 建表格追溯索引；
6. I01/I02 分别与 B07/B08 做完整历史跨进程确定性比较：`economic_config_hash` 和排除身份列后的业务键表相同；完整 manifest 哈希因运行身份不同而不要求相同；
7. 机器完成后标 `COMPLETE_NONCANONICAL` 并生成待人工复核清单；
8. 项目所有者或指定复核人签署 `manual_review.json` 后，由晋升工具原子写入 `outputs/CANONICAL_V6.json`；未签名不得自称 canonical；
9. 完成 v6 后停止，不自动执行 v6.x/v7。

## 11. 立即停止条件

### 数据

- 关键端点静默空返回；
- 映射合约缺行情；
- 限价无法取得或因果推导；
- 费率或保证金单位无法确定；
- 数据/规则哈希在运行中变化。

### 未来函数

- 追加未来数据改变历史日历、Panama、信号、限价、margin as-of 或订单；
- runner-up 使用 t+1 排名；
- 订单在信号形成前成交；
- 报告域未来合约身份流入交易域。

### 账户

- 金额残差>0.01元；
- 持仓或订单数量残差非零；
- 滑点/手续费重复扣除；
- 内部目标被收费；
- roll/跨零状态无法复原。
- 出现 `ACCOUNT_INSOLVENT`；保留触发前账本并停止，不得临时启用强平或合成收益曲线继续排名。

### 实验治理

- compatibility 闸门失败且无法解释；
- 注册表在结果产生后被改写；
- 启动新完整历史任务前，全局 `attempt_count >= 48`，或 `48-attempt_count < 44-effective_count`；
- 只保留优胜场景或删除失败目录；
- 代理结果被要求描述为真实结果。
- 任何人试图以“端点闪断/OOM”为由删除或返还已写入 `STARTED` 的 attempt；基础设施失败只能依靠启动前探针、迷你市场和检查点降低概率，仍须占用预留槽。

## 12. 失败后的处理

停止不等于删除：

1. 将 `RUN_STATUS.status` 改为 `FAILED_GATE`，并把具体失败闸门写入 `failed_gate_id`；
2. 保存最后成功阶段、失败测试、最小复现和差异表；
3. 输出 `V6_BLOCKER_REPORT.md`；
4. 不生成策略优劣结论；
5. 若后续修复，使用新时间戳目录并保留旧 attempt；
6. 不自动放宽阈值或改研究设计。

## 14. 最终交接必须回答

1. 修正后 v3 的正式 CAGR、Sharpe、最大回撤、成本、杠杆和保证金是多少？
2. 旧结果与新结果的差异分别由手续费、限价、保证金和动态反馈贡献多少？
3. 固定 50:50 袖套是否仍改善年份集中、FG 依赖和最大回撤？
4. 20skip5 与 250 在回撤期是否仍低相关，低相关来自哪些板块/品种？
5. 锁板政策对结论是否重要，证据是否足够？
6. 22 候选在多重比较后是否有任何一个可靠优于 v3？
7. 真实滚动选择与旧固定切片差多少？
8. 哪些费用、限价、保证金仍是代理，影响有多大？
9. 是否推荐替换 v3；支持和反对证据各是什么？
10. 哪些结论不能据此得出？
11. v6 显性成本中手续费、基础/换月/冲击滑点各占多少，冻结路径 ±1 tick 诊断是否足以改变定性结论？
12. Westfall–Young 在本样本长度和依赖强度下的设计功效是否足以识别有经济意义的差异？

## 15. 后续研究候选的存放

执行中发现的新想法只写入 `future_research_candidates.md`，包括信号频率、AL→AG、小资金宇宙、第三方引擎、早期样本、固定多品种、0.5 tick 等；本轮不运行。

## 16. 完成定义

v6 的**成功技术完成**必须同时满足：

- 全部强制闸门通过；
- 44 个计划有效运行在全局 48 次尝试上限内完成；
- 全部底层表、CSV/pickle、测试和中文报告存在；
- 技术完成时项目级 canonical 指针尚不存在或仍合法指向既有旧版本，且绝不能提前指向本次未签名 run；人工签名晋升后才要求 `CANONICAL_V6.json` 唯一指向本 run；
- 历史目录未被修改；
- 最终结论遵守样本污染和代理限制；
- 完成后停止，不自动进入下一版本。

若按预注册停止条件提前结束，这属于 `FAILED_GATE`、`INTERRUPTED` 或仅供诊断的 `PROVISIONAL` 交接，不属于完成；只生成 `V6_BLOCKER_REPORT.md` 和已有证据清单，不生成正式策略优劣报告，也不得标记 `COMPLETE_NONCANONICAL`。
