# v6 审计问题登记簿与处置矩阵

## 1. 使用规则

本表把审计意见分为：

- `阻断`：未关闭前禁止发布任何 v6 业绩；
- `高`：可完成局部技术验证，但禁止形成投资结论；
- `中`：必须在最终报告披露并有测试或诊断；
- `低`：工程治理项，可在不改变结果的情况下收口。

状态只能是 `OPEN`、`PARTIAL`、`CLOSED_TESTED`、`ACCEPTED_PROXY` 或 `NOT_APPLICABLE`。不能只以“代码已修改”标为关闭；至少要有自动测试和底层运行证据。

## 5. 对三个指定文件内容的采纳判断

### 5.1 直接采纳

- `重跑结果清单.md` 的 R1—R3 优先级：手续费、锁板、逐日保证金必须先于新信号研究。
- R4 的信号独立复算作为强一致性证据；v6 还要把范围扩展到原始数据→Panama→信号的端到端独立复算。
- R5 对 v1/v2 费用结论作废。
- R6 对验证期择优和伪 walk-forward 的纠正。
- R7 对 Panama 百分比口径的清理。
- `修改方案文档.md` 中逐合约下载、显式告警、锁定依赖、稳定排序、输出配置化。
- `HANDOFF_REPORT_下一轮.md` 中把锁板买卖侧政策作为有限对比，并保留所有失败/中断留痕。

### 5.2 采纳但改写

| 原建议 | v6 改写原因 |
|---|---|
| `trading_fee_rate` 一律 `/1000` | 大方向正确，但 v6 不采用单一启发式；按端点字段、交易所、品种和时期显式声明单位，T 专用固定费规则独立 |
| `reported > 0` 就替换静态保证金 | 不充分；还要按多空方向、单位、as-of、客户加成和缺失策略处理 |
| 锁板后截面换次优 | 这是策略变化，不是执行修复；必须是 t 日已预生成的条件单并作为独立研究场景 |
| 真实保证金使结果“更真实/更好” | 只能说静态代理在现有覆盖的冻结诊断中总体偏紧；特殊提保日未必如此，动态仓位反馈和客户加成也会改变结果，不能预设方向 |
| 21 个 iid 正态最大值判断胜者偏差 | 只能作启发式；正式采用所有策略共享区块的联合 Bootstrap 和预注册的 Westfall–Young step-down max-t |

### 5.3 明确不采纳

- 不用所有合约全历史 `high==low` 直接标记锁板；该口径产生大量假阳性。
- 不用当日 `high/low/settlement` 在开盘成交后才识别“开盘锁板”；这会产生时点错误。
- 不把事后删除锁板成交当正式重跑；只能作冻结路径诊断。
- 不把冻结成交的费用重算当动态回测；它没有权益反馈。
- 不把临时重跑目录或缺底层表的报告提升为正式基准。
- 不把旧代码健康分数 60/100 当作 v6 验收阈值。
- 不把 v2+ 未实际出现的缺日问题写成已观察事实；只保留为防御性测试。
- 不把静态保证金结果称为有保证的收益下界。

## 6. 问题关闭所需证据

每个 `CLOSED_TESTED` 问题至少必须有：

1. 一个代码变更或明确的数据规则；
2. 一个能够在旧缺陷上失败、在新实现上通过的定向测试；
3. 一个可人工复核的最小样例；
4. 一个生产数据覆盖/异常统计；
5. 一个修复前后单因素差分；
6. manifest 中的输入、规则和代码哈希；
7. 中文报告中的限制说明。

## 7. 审计问题影响链

```text
端点空返回
  ├─ 无逐日保证金 → 约束路径改变 → 手数/成交/成本/收益改变
  └─ 无上下限     → 幽灵成交       → 换月/反手/持仓暴露/收益改变

费率单位错误
  → 直接手续费错误
  → 权益改变
  → 后续波动率目标和手数改变
  → 后续手续费、滑点、保证金与收益再次改变

验证期择优
  → 胜者偏差
  → 历史 Sharpe 上偏
  → 不能把 2022—2026 称为干净样本外
```

因此 v6 的修复必须按单因素阶梯运行，不能一次全部改完后只比较最终收益。
