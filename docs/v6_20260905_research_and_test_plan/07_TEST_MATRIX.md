# v6 自动化测试、手算和独立验证矩阵

## 1. 测试分层

| 层级 | 目标 | 是否阻断 |
|---|---|---:|
| 静态与 schema | 禁止错误类型、私有跨层依赖、缺字段和不稳定主键 | 是 |
| 单元测试 | 公式、边界、状态转换 | 是 |
| 性质/前缀测试 | 因果性、不变量、单调性 | 是 |
| 手算测试 | 人工可复核的金额和持仓 | 是 |
| 集成测试 | 数据→信号→订单→账户完整链 | 是 |
| 历史回归 | 兼容模式逐表复现旧正式结果 | 是 |
| 差分测试 | 每项修复只改变允许的对象 | 是 |
| 独立复算 | 不复用引擎账本逻辑重建结果 | 是 |
| 确定性测试 | 跨进程、排序、哈希、CSV/pickle | 是 |
| 统计测试 | Bootstrap 同路径抽样、滚动选择无偷看 | 是 |

旧缺陷见证测试与当前绿色测试分开运行。`EXPECTED_FAILURE_WITNESS` 不得计作 v6 失败，也不得混入“全部通过”数字。

## 2. 数据和日历测试

### 单元/边界

- 单合约 endpoint 正常、0 行、权限不足、重试后成功、永久失败；
- 固定 RB/SC/M/TA/T 各 15 日，共 75 个含夜盘/无夜盘样本，核验 `fut_daily.open` 是该交易日哪个 session 的首开并核对交易日归属；任一不一致阻断；
- 五所各 2 个历史/活跃合约的 `ft_limit` 权限探针能区分有数据、无权限、未上市和真实空区间；
- 批量参数被拒时不能写成成功；
- 重复主键同值去重、冲突值硬失败；
- 上市前、退市后、休市和真实缺失分类；
- 日历跨春节、国庆、临时休市和跨年；
- 未完成周/月不生成信号；
- 多交易所不同休市安排；
- 新增下一周数据不改变过去完整周标记。

### 生产审计

- 每品种/合约/年份 coverage；
- 映射合约无 bar 数必须为 0；
- multiplier/tick_size 合约内不变断言或 effective-dated 规则边界；
- 主键重复必须为 0；
- 非正 OHLC 必须为 0；
- 关键字段缺失按原因分类；
- 数据文件行数与 manifest 一致。
- 同一规范表打乱输入行序、跨 pandas 版本读回后，`canonical_json_rows_v1` 内容哈希不变；任一业务值改变后哈希必须改变，pickle 文件字节不得充当内容一致性真值。

## 3. 主力映射和 Panama 测试

- vendor mapping t 日收盘决定、t+1 首次交易；
- OI 回退确认天数与 1.10 切换比边界；
- 到期最晚换月和禁止倒退换月；
- 换月前 10 日内重叠价搜索，窗口边界手算；
- 没有共同价时保持缺失/失败，不向未来查找；
- 追加未来行情不改变历史 mapping、roll gap、Panama；
- 连续价点差和手算一致；
- Panama 正价差手算：old=100、new=110 时 gap=+10；反向手算：old=110、new=100 时 gap=-10；两者加到换月前历史后都与新合约对齐；
- 对 `CONTINUOUS_POINT_SERIES` 调 `pct_change` 必须失败；
- `FORWARD_CONTRACT` 不能被交易模块 import 或访问。

## 4. 信号和选择测试

- 20、60、120、180、250、252 日完整窗口边界；
- 20 日跳 5 日确实排除最近 5 个交易日；
- 250 减 20 使用正确价格区间，不是两个 Sharpe 相减；
- 点差年化 Sharpe 公式和零波动处理；
- scaling 至少滞后一日、最小历史样本、截断 [-20,20]；
- 缺失周期不得隐性动态重加权；
- 农业和化工只在各自板块的当日合格品种内排名；
- 最高值必须>0才做多、最低值必须<0才做空；
- 无正/负信号时相应预算空置；
- RB/T/AL 只按 forecast 正负做绝对方向；
- runner-up 在 t 日生成且不因 t+1 新排名变化；多头按 forecast 降序、空头按 forecast 升序，同分按 instrument/ts_code 字典序；
- runner-up 使用自身截至 t 的点差波动率和合约乘数重新定整数手，只承接主选未成交风险预算；不得复制主选手数、级联第三名或转移空缺预算；
- 独立 numpy/pandas 实现与引擎 scores/selections/targets 一致。

## 5. 手续费测试

### 规则和生效边界

- 每个正式品种至少一个规则生效边界样例；整个测试集分别覆盖固定每手费类别和按成交额比例费类别；
- RB、SP 的官方费率变更日前一天/当天/次日；
- T 固定费字段漂移不会走比例除数；
- 客户倍数 1.0、1.5 的线性关系；
- 精确合约规则优先于品种通配，临时公告优先于一般表；同优先级重叠规则必须失败而不是取最后一行；
- 代理规则只命中声明区间；
- 缺关键规则 hard fail，不使用全局 5 元或 2bp `max`。

### 交易类型

- 纯开仓、隔夜平仓、平今；
- 多→空、空→多跨零拆分；
- 部分成交；
- 换月旧腿平仓和新腿开仓各一次；
- oldest-lot-first 分配；SHFE/INE 显式先平昨再平今，其他交易所账本先昨后今；
- 拒单、过期单、内部目标手续费为 0；
- 持仓批次 FIFO/交易所指定平仓语义与配置一致。

### 性质

在冻结 fills 下：

- 客户倍数提高，手续费不得下降；
- 正确费率与旧费率的权益差精确等于手续费差；
- 动态重跑不强制线性，但必须能由订单路径差解释。

## 6. 限价和订单状态测试

- 上限 BUY、下限 SELL 拒绝；
- 上限 SELL、下限 BUY 属价格侧可成交方向；新增风险仍需通过风险/保证金，平仓属性不能覆盖错误价格方向；
- 非限价开盘执行；
- 不利滑点后越界时成交价夹在限价内，若无可成交价则拒绝，并勾稽 requested ticks、executed ticks、grid rounding 和 limit-clip reduction；
- 限价来自 `OFFICIAL_DAILY/OFFICIAL_RULE_DERIVED` 且执行前可知；
- 当日 high/low/settlement 变化不改变开盘前限价；
- 全历史因果上下限包住当日 observed high/low；违反时 hard fail。该性质测试明确标注“必要非充分”，不能把通过当作官方限价证明；
- 参与率上限造成部分成交；
- 拒单/部分成交后的持仓连续；
- 跨零平仓未完成前不新开；
- roll close-first、匹配部分数量和双边费用；
- L0 次日重算、L1/L2 精确一次顺延；
- runner-up 无级联、无动态预算转移；
- 审计的主力 12 个一价形态日、7 段旧成交/4 段逆向成交和 RU2505 关键旧腿作为挑战集；逐点先核实来源与方向，只有确认的逆向实际订单才断言拒单。

## 7. 滑点和冲击测试

- BUY 向上、SELL 向下不利；
- 0/1/2/3 tick 网格精确；
- 基础、换月、冲击 tick 加总；
- 参与率 1%、3% 边界；
- 固定 3 tick 覆盖基础层，但不重复添加基础 tick；
- 滑点金额等于手数×价差×乘数；
- 滑点仅进入 fill price 一次；
- 冻结订单下更高滑点不产生更好现金结果；
- 日线模型不可生成 0.5 tick 成交。

## 8. 保证金和风险测试

- long/short 使用各自 rate；
- T 2.0→0.02 的单位表驱动转换；
- 客户代理×1.25 与交易所最低率分列；
- as-of 生效日前后；预交易不得读取执行日收盘后的结算价或 margin row，日终占用才允许使用当日结算；
- 缺失才回退，不使用 `max`；
- 保证金不从权益扣除；
- 平仓不受保证金阻止；
- 开仓缩量后整数手且不越上限；
- T 不进入商品上限，但进入总保证金/杠杆报告；
- 五板块相对风险预算固定；
- 无信号风险份额不转移；
- 协方差只产生单一组合缩放，不改变相对预算；
- 10% buffer 只在组合缩放后的最终真实净目标作用一次；成交量/OI、保证金和杠杆硬约束在其后覆盖，目标硬约束降险、清仓、换月和 120% 紧急减仓不受 buffer 阻止，但不得冒充经纪商强平；
- 经协方差缩放（最高 3 倍）与实现波动反馈（最高 1.35 倍）后，最终手数仍不得超过 `floor(volume_median_20*5%)` 或 `floor(oi_median_20*1%)`；用会触发两个放大上界的 fixture 验证，并断言硬约束后没有再次放大；
- 120% 紧急减仓优先级和原因码。
- 构造日终实际保证金占用超过 65%/78% 的情形，验证只记录 breach 诊断，并由下一次标准目标约束产生 `MARGIN_TARGET_REDUCTION`；不得出现 `MARGIN_CALL_LIQUIDATION`、伪造成交或新增经济路径。
- 构造权益恰为零与跨零为负的情形，验证写入 `ACCOUNT_INSOLVENT` 后立即停止、保存触发前部分账本、attempt 仍计数，且不生成后续收益、合成 -100% 曲线、排名或 Bootstrap 输入。
- 在 A01—B08 的迷你市场和完整历史闸门中断言 `ACCOUNT_INSOLVENT` 事件数为 0；若非零，按 G6 停止而不是切换强平政策。

## 9. 袖套净额测试

- 每板块内 20skip5 与 250 各 10% 固定风险；
- 两侧同向相加、反向净额；
- 一个袖套缺失时另一袖套不扩权；
- 内部虚拟交易不收费；
- 只对合约层最终净差下单；
- 跨不同真实合约不能错误净额；
- 换月前后旧/新合约分别保留；
- 风险约束和 buffer 仅一次；
- 内部目标之和、净额前后目标和真实订单数量全链可追溯。

## 10. 会计手算样例

至少建立 8 个独立 fixture：

1. 单品种开多—隔夜—平仓；
2. 开空—隔夜—平仓；
3. 当日开平和 close_today；
4. 多→空跨零；
5. 换月两腿；
6. 限价拒单后次日重算；
7. 参与率部分成交；
8. 两袖套反向目标净额后成交。

每个 fixture 附人工表，逐日列开盘、结算、持仓、成交、毛盈亏、手续费、滑点归因、保证金和权益。期望值不得由被测引擎生成。

## 11. 集成和差分测试

### 迷你市场集成

构造至少两个交易所、三个品种、两个真实合约、一次换月、一次锁板、一次反手和一次保证金变化的 30 日数据集。完整跑通数据→报告。

### 修复阶梯差分

- A06→B01、A04→B02：score、eligibility、selection、direction 及第一笔手续费差出现前的目标必须相同；手续费改变权益后目标允许动态变化，但每个变化必须追溯到权益/仓位反馈；
- B01/B02→B03/B04：只允许限价相关订单状态及其后续反馈变化；
- B03/B04→B05/B06：只允许保证金约束及其后续反馈变化；
- B05/B06→B07/B08：只允许风险放大后最终流动性/OI 硬约束及其后续反馈变化；
- B08→D01/D02：信号不变，只允许锁板政策影响订单及后续反馈；
- B08→C03：信号/目标形成相同，滑点和动态反馈可变。

## 12. 未来函数和前缀测试

对随机选择的固定 30 个截点（种子 20260905，不计完整历史 attempt），以及所有换月/费率/保证金/限价生效边界做 prefix test。前缀运行与完整运行共同日期必须相同，显式覆盖点差波动率、20日流动性中位数、252日协方差统一缩放、63日实现波动反馈和紧急减仓。测试要覆盖缓存命中和重新构建两条路径，防止缓存掩盖未来依赖。

## 13. 独立复算范围

独立实现不能调用 `ledger.py`、`fee_schedule.py` 或其私有函数。输入为规范 bars、规则表、orders/fills，独立重算：

- 每笔费用；
- 每日逐合约持仓；
- 结算盈亏和权益；
- 滑点归因；
- 保证金占用；
- 贡献汇总；
- 信号/选择/目标抽样。

R4 既有逐位复算可以作为锚点，但 v6 还要覆盖原始数据到 Panama 的上游，避免共同规格错误。

## 14. 统计测试

- CAGR、算术252年化、Sharpe、Sortino、MDD、Calmar、已恢复/未恢复回撤和不完整年度各有小数组手算；
- 22 个策略每次 Bootstrap 使用完全相同的日期索引；
- block 不跨样本区间边界；
- 给定种子抽样明细完全一致；
- 配对差由同一重复中的两策略计算；
- 针对配对平均日净收益的 Westfall–Young 去均值、Bartlett HAC lag=20、step-down 排序、调整 p 值单调性用 3 策略×20 日人工矩阵验证；另断言 Sharpe 差输出带 `multiplicity_adjusted=false`；
- Westfall–Young `gamma_l` 分母 n、`(1+exceed)/5001` 和非正 HAC 方差=`NOT_TESTABLE` 各有边界手算；可检测门槛表的 `critical_t*HAC_SE` 与原始 bootstrap 临界分位逐值对应；
- 冻结 fills 基础滑点 -1/+1 tick 只改允许的成交价归因；低于 0 截为 0、保持整数 tick、限价不可重定价行单列，且不得生成动态回测标识；
- `D_obs` 年化公式用不完整年度小数组手算，主选择表仍只读取 252 口径；
- I01/I02 分别与 B07/B08 的 `economic_config_hash` 相同、完整 manifest 哈希不同；排除注册身份列后按 `business_event_key` 比较业务表完全一致；
- B07/B08 与 I01/I02 使用不同 `PYTHONHASHSEED`，结果仍按业务键一致；静态扫描禁止用裸 `set`/`dict` 迭代决定排名、事件序号或订单顺序，所有并列必须显式稳定排序；
- `V6_MACHINE_REGISTRY.yaml` 必须恰有 44 个唯一 scenario、连续 sequence=1..44、22 个唯一基础策略且 provider 可解析；与 narrative registry/resolved config 逐字段一致；
- 压力场景/留一结果不进入基础策略集合；
- 滚动选择只看训练窗，下一年选择固定；
- 年初换策略产生真实过渡订单；
- 不完整 2026 不进入完整年度选择评分；
- 人工 2 窗小样例验证选择和拼接。

## 15. 质量阈值

- 费率、限价、保证金、订单状态机、账本模块的可达业务分支覆盖率目标 100%；仅允许在 `coverage_exclusions.yaml` 中逐行登记并人工说明真正不可达/平台专属分支，禁止无理由 `pragma: no cover`；
- v6 新包整体行覆盖率≥90%、分支覆盖率≥85%；
- 所有 P0 缺陷至少有一个“旧实现失败、新实现通过”的定向测试；
- 全套绿色测试 0 failure、0 unexpected xfail；
- flaky 测试重复 5 次不得漂移；
- 报告列出的测试数必须从机器生成的测试结果读取，不手填。
