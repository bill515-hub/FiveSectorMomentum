# v6 版本谱系、历史结果白名单与基准定义

## 1. 版本继承关系

```text
v0.1 / MVP
  └─ core: 数据归一化、主力映射、Panama、基础信号和事件引擎
      └─ v2: 数据与流动性/风险约束改进
          └─ v3: 历史手续费、滑点、冲击、调仓频率与成本研究
              └─ v4: 不同周期、跳过近期、多周期 forecast
                  └─ v4.1: 成本反事实、袖套、相关性与联合 Bootstrap
                      └─ v4.2: 独立周度日历修复、20skip5/250 固定袖套
                          └─ v6: 审计后重构、纠错基准、固定策略复核
```

现有实现并不是一个从 v0.1 到 v4.2 完全替换的单体。它是核心模块加多个版本化扩展：v4 继承 v3 执行，v4.1 复用 v4 信号与 v3 账户，v4.2 又复用 v3/v4/v4.1 的部分私有函数。v6 因此不能再简单增加一个巨大的 `engine_v6.py`，而应建立新包和清晰接口。

这里的“v6”是用户指定的新研究方案编号，不表示原计划中的 v5 已经实施或验证。v6 不得引用任何不存在的 v5 结果作为证据。

## 4. 关键术语不能混用

| 名称 | 定义 |
|---|---|
| `reference_v3_252` | v3 正式参照，完整 252 个交易日窗口 |
| `single_250` | v4 的 250 日经济对照，不等同于 v3 252 日参照 |
| `single_20_skip5` | 20 日观察窗口跳过最近 5 个交易日的短周期候选 |
| `sleeve_20skip5_250_equal_risk` | 每板块 20% 风险预算内，20skip5 与 250 各占固定一半；空缺份额不转移；真实合约净额后只执行一次风险/buffer/收费 |
| “切片敏感性” | 对固定策略按年份或区间展示结果 |
| “真实滚动选择” | 每个训练窗只用当时可见数据选规则，下一年固定运行，再滚动；不能把切片称为该方法 |
| “历史验证期” | 2022—2026，已经被多轮查看，不再是干净 OOS |
| “未来冻结样本” | 2026-09-05 注册后首次出现且未用于设计的数据 |

## 5. 现行信号与执行链事实

```text
t 日收盘及此前数据
  → 完成周期判定
  → Panama 点差 forecast
  → 当日横截面/绝对方向
  → 风险目标与内部袖套目标
  → 真实合约净额目标
  → 组合统一风险缩放
  → 正常 buffer
  → 保证金/杠杆硬约束覆盖
  → 生成订单
  → t+1 首个可交易时点成交或拒单
  → 当日结算盯市与账户入账
```

文档应分别记录：

- `decision_time`：信号和候选条件单形成时间；
- `target_effective_time`：目标可首次生效时间；
- `execution_time`：下一交易日供应商日线定义的首个 session open；夜盘品种可能是前一民事日晚间，不等同于统一的日盘开盘；
- `data_asof_time`：每个数据字段当时何时已知。

不得用含糊的“lag=0/1”代替这四个时间。

## 6. 风险权重和相关性的准确表述

现有研究意图是：

1. 五个板块各占固定 20% 风险预算；
2. 品种或周期内部按各自波动率换算手数；
3. 相关性不改变板块之间或袖套之间的相对预算；
4. 若启用 252 日协方差模型，它只计算一个全组合统一杠杆缩放系数，使预期组合波动接近目标；
5. 未使用的风险份额保持现金，不向其他板块或周期动态转移。

因此准确说法是：**相对权重只看预先固定的风险预算和各自波动率；总组合统一缩放可以看历史协方差。** v6 必须提供保留/关闭统一协方差缩放的纯风险模型诊断，但不得用它优化相对权重。

## 7. v6 比较基准

v6 设置三类角色：

| 角色 | 场景 | 用途 |
|---|---|---|
| 历史兼容参照 | 原 v3/v4.2 G1/G2/S1/S2 | 检查 v6 适配器是否引入无关漂移 |
| 审计修正正式基准 | `reference_v3_252` + 全部已确认执行修复 | 新的正式会计与执行参照 |
| 固定研究候选 | `single_20_skip5`、`single_250`、固定 50:50 袖套及预注册锁板政策 | 判断既有研究结论是否稳定 |

候选不能因中途结果而新增。2022—2026 指标只能称“历史验证重估”。

## 8. 历史数字锚点的使用方式

原 v3 正式基准和临时费用修正重跑可用于识别数量级，但不能混成一个正式结果：

- 原 v3：净利润约 45,639,975.35 元、手续费约 1,272,704.65 元、成交 417,534 手；
- 临时修正费用重跑：净利润约 43,694,213.86 元、手续费约 1,715,216.14 元、成交 407,319 手；
- 两者的净利润差不等于手续费差，证明动态权益会反馈到后续目标和成交。

v6 闸门不得只比较最终净利润。必须同时比较订单、成交、每日持仓、成本、权益以及风险约束触发路径。

## 9. v1/v2 的处置

v1/v2 对 T 的费用回退约为 205—207 元/手，而正确客户口径约 3.6 元/手。v6 报告必须：

- 给 v1/v2 成本、净利润、Sharpe 字段增加 `VOID_COST_MODEL` 状态；
- 禁止 v1/v2 数值进入 v6 正式排名、成本弹性或收益比较；
- 允许保留其架构演化和信号方向作为历史背景；
- 明确该错误即使重新取得 T=3 元/手数据也不会自动消失，因为旧逻辑取了高额名义费率回退的 `max`。

## 10. 2026 年的完整性

任何截止 2026-09-05 或更早的运行都包含不完整的 2026 年。年度表必须有 `is_partial_year` 字段，并禁止将 2026 与完整年份做未经年化或未经标记的排名。
